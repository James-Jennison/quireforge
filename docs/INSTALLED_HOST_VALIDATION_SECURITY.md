# Restricted installed-host validation

The repository-owned helper is installed only as `/usr/local/sbin/quireforge-validate-deb`. It is a narrow root boundary, not a package manager or a general command runner. Production remains disabled until separately approved installation and real validation work.

It accepts exactly one UTF-8 JSON document (at most 4 KiB) on stdin and no arguments: `schema_version`, `session_id`, `nonce`, `expected_application_version`, and `expected_debian_version`. This snake_case form is the sole request wire schema; camelCase and aliases are rejected. Stdin is untrusted: unknown, missing, trailing, or malformed data is rejected. Candidate and project identity remain native-owned and never cross this boundary.

Its single canonical snake_case stdout result has `schema_version`, `session_id`, `nonce`, `outcome`, `facts`, and `result_sha256`. Facts contain only `kind`, `schema_version`, `package_state`, `version_match`, `ownership_verified`, `permissions_safe`, and `package_integrity_verified`. The digest covers the complete result except itself. No paths, package lists, commands, output, metadata database, commits, host data, or credentials are read or emitted.

The helper uses fixed absolute dpkg tools and fixed installed paths, checks package ownership, root ownership, regular non-symlink protected files, safe modes, and package integrity. Application version is derived only from the fixed Debian version using the release contract's first `~` to `-` mapping; `/usr/bin/quireforge` is never invoked as root because native argument handling does not establish a side-effect-free version mode. It never launches a GUI; the unprivileged visible-launch proof remains authoritative. It never opens QuireForge metadata.sqlite3.

For a future approved installation, use root-owned helper mode 0755 or stricter and root-owned sudoers mode 0440, validate the sudoers file with `visudo -cf`, then invoke only `sudo -n /usr/local/sbin/quireforge-validate-deb` with the request on stdin. The tracked example grants no interpreters, shells, package managers, arguments, or alternate paths.

Authorization is deliberately limited to the administrator-managed `%quireforge-package-validation` group. The helper never creates this group: an administrator must explicitly add the intended owning desktop user. Membership grants only the exact no-argument helper as root, not any underlying tool. Membership changes take effect after the usual session refresh or relogin; removing a user revokes future authorization. Do not replace this group with wildcard users, `%sudo`, `%wheel`, or a broad desktop-user group. Installation remains a separate explicit approval.

The native installed-host caller is internal-only: after migration, it resolves one trusted native context, verifies the installed Debian version, records or reuses the fixed unprivileged phase, revalidates its digest-bound receipt, then invokes exactly `/usr/bin/sudo -n /usr/local/sbin/quireforge-validate-deb`. Missing authorization, sudo, helper capability, migration, candidate, or unprivileged validation produces no installed-host attempt. The native request includes only a fresh session, nonce, and predecessor versions. The immutable attempt identity binds the candidate identity, outcome, and every closed helper fact (kind, fact schema, package state, version match, ownership, permissions, and integrity), never session, nonce, paths, host data, or diagnostics. Production cannot succeed until helper and sudoers installation receive separate approval.
